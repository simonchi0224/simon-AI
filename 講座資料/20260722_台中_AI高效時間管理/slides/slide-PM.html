手上有：交辦訊息、會議逐字稿、三份舊資料、一張參加名單、一份舊簡報

WORKFLOW · 會議前、中、後

會議不是開完就結束

AI 在會議前中後，分別能幫上什麼忙
會議前
根據背景資料產出議程、待確認問題、會前資料摘要
會議中
逐字稿或錄音——保留前，先確認參與者同意與單位規定
會議後
提取決議、行動項目、負責人、期限、待確認事項；轉成主管摘要與參與者通知信
會議後一定要人工核對：發言人、數字、日期，以及「真正形成的決議」是不是AI摘要出來的那樣。
補充：部分平台（如 ChatGPT Record）可轉錄會議與語音筆記，但受方案與裝置限制，且要求使用者自行取得參與者同意 · 資料來源：OpenAI 官方說明
FRAMEWORK · 帕金森定律

會議排一小時，
就會開滿一小時

不是內容需要那麼久，是時間允許它那麼久
帕金森定律（Parkinson's Law）
工作會膨脹，直到填滿你分配給它的所有時間——會議、報告、審核，只要沒有明確的時間限制，就會自然拖長。
資料來源：C. Northcote Parkinson, 1955
對主管的應用
開會前先問：這件事真的需要一小時嗎？能不能訂30分鐘、附議程？時間限制訂得越清楚，AI幫你整理的會議紀錄也會越聚焦。
今天下午每個練習都有建議時間——不是隨口訂的，是刻意讓你練習「先設時間框，再做事」。
FRAMEWORK · 資源撫平 Resource Leveling

班表衝突，
是一個有名字的專案管理問題

8位老師/社工的月班表衝突——這正是資源撫平要解決的事
資源撫平（Resource Leveling）
當同一群人被多個任務同時需要、超過負荷時，調整任務的開始/結束時間或順序，讓人力負荷不要同時衝到最高點。
資料來源：PMI《PMBOK Guide》時程管理知識領域
主管怎麼開始
列出每個人這個月要做的事跟預估時數，找出哪一週所有人都在同一個時段被需要——那就是要優先調整的地方。
這件事AI可以幫忙整理數據（誰在哪一週被排了幾件事），但「怎麼調整、跟誰談」，還是你的判斷。
🗒️ 便利貼活動 · 把團隊任務貼上週曆

用便利貼，
看出誰的負荷卡在哪一週

白板畫四週格線＋便利貼（一人一色最好）個人或小組6分鐘
  1. 白板畫出橫向四週的格線本月第1週到第4週
  2. 想你團隊裡的成員，每人選一個顏色的便利貼沒有分色便利貼，就在角落寫名字縮寫
  3. 把每個人這個月的任務，寫便利貼貼到對應的週次家訪、課後輔導、會議準備都算
  4. 看哪一週同一顏色貼得特別密集那就是負荷過高的那一週，需要調整
DEMO · 會議後

把逐字稿變成行動清單

ChatGPT / Gemini
Prompt 範例
以下是跨單位協調會的逐字稿（不整齊沒關係）：[貼上逐字稿] 請幫我整理成三個區塊： 1. 決議事項 2. 行動清單（每項附負責人與截止日，從逐字稿推斷，不確定的標示「待確認」） 3. 下次會議需跟進的問題 用條列格式，清楚簡潔，個資部分請用代號呈現。
貼進去之前，記得把真實姓名先換成代號——這是上午第2堂練過的去識別化習慣，下午開始正式上場。
進階技巧 · 多人發言怎麼分開整理

ABCD 一起開會，
怎麼分別看出每個人說了什麼

學員實際問過的問題：AI 常常把整段對話混在一起摘要，看不出「B 說了什麼、C 又回應了什麼」
關鍵在來源，不是在提示語
如果逐字稿本身沒有標記「誰在說話」，AI 猜不出發言者是誰——先確認逐字稿或錄音轉出來的文字，有沒有標好 A／B／C／D 或姓名代號。
Gemini Notebook 比對話型AI更適合
把有標記發言者的逐字稿當作來源上傳，之後可以個別問「代號A對這個提案的意見是什麼」「代號B跟代號D的看法有沒有衝突」，它會回到原文找答案，不是整段猜。
ChatGPT / Gemini（沒有Notebook時的替代做法）
Prompt 範例
以下是逐字稿，發言者已標記為代號A、B、C、D：[貼上逐字稿] 請依照發言者分別整理：每個人各自的重點主張是什麼， 最後再另外整理一段「共識與分歧」，標出誰跟誰意見一致、誰跟誰看法不同。
沒有標記發言者的逐字稿，先用語音轉文字工具（很多學員已經在用）轉出來時就標好代號，比事後請AI猜準確得多。

SCENARIO · 三份舊資料要整理

多份文件，怎麼一次看完

案例：手上有三份舊活動的檢討報告，要整理出這次能用的重點
  • 把多份文件集中到同一個專案或 Gemini Notebook而不是一份一份分開問
  • 要求 AI 比較不同版本的差異、共通點與衝突
  • 從資料中提取日期、金額、對象、規定、負責單位
  • 整理出缺漏、重複資料及需要補充的問題

DEMO · Gemini Notebook

把三份舊資料丟進去，直接問重點

Gemini Notebook
來源：3 份文件已上傳
你問：這三次活動的檢討報告裡，最常被提到的問題是什麼？請附上分別出自哪一份文件。

SCENARIO · 給董事會的報告

簡報初稿，從一句話開始

先想清楚，再交給AI搭架構
  • 用一句話寫出這份簡報要解決的問題不是「介紹活動」，是「說服董事會核准什麼」
  • 根據對象決定：背景、現況、方案、時程、行動要求
  • 從長篇資料裡，提取每一頁的標題與佐證內容
  • 請 AI 建議哪些內容適合表格、流程圖或時間軸
  • 產出演講備註，以及可能被問到的問題先準備，臨場比較不慌
確認過內容後，可以用 Gamma 或 Canva 把大綱轉成有版面的簡報初稿，再自己微調。

FRAMEWORK · 看板方法 Kanban

用三欄，
看清楚事情卡在哪裡

待處理 / 進行中 / 已完成——工作追蹤表的方法論來源
待處理
還沒開始，但已經進入視野的工作
進行中
正在做，標出負責人跟卡點——這一欄最容易被忽略，也最需要主管關注
已完成
做完了，留下紀錄，之後寫週報直接引用
起源於豐田生產方式（Taiichi Ohno），後由 David J. Anderson 系統化應用於知識工作管理
接下來的工作追蹤表，就是這三欄的概念——差別是，AI 幫你把資料維護起來，你只要看「進行中」那一欄有沒有卡住。
🗒️ 便利貼活動 · 畫出你自己的看板

白板畫三欄，
把手上的任務便利貼分類貼上

白板畫三欄＋便利貼個人或小組5分鐘
  1. 白板畫出三欄：待處理／進行中／已完成
  2. 把你手上（或團隊）目前的任務，一件一件寫便利貼可以用上午寫過的清單，也可以想新的
  3. 貼到對應的欄位「進行中」的便利貼，額外標上負責人跟卡點
  4. 看看「進行中」那欄有沒有便利貼卡了很久這通常就是團隊裡沒被注意到的問題
FRAMEWORK · RACI 責任矩陣

看板顯示「卡在哪」，
RACI回答「該找誰」

一件任務，四種角色
R 執行者
Responsible——實際動手做的人
A 負責人
Accountable——對結果負最終責任，通常是你
C 需諮詢
Consulted——執行前要先問過意見的人
I 需告知
Informed——完成後要讓他知道的人
資料來源：PMI《PMBOK Guide》責任分配矩陣（Responsibility Assignment Matrix）
給團隊每件任務標上這四個角色，很多「以為交辦了、其實沒人真的負責」的狀況就會消失。
🗒️ 便利貼活動 · 把名字貼進RACI表格

白板畫表格，
幫一件任務指派四種角色

白板畫表格＋寫好團隊成員名字的便利貼個人或小組5分鐘
  1. 挑一件你手上正在做的專案或活動例如：董事會報告、跨單位活動籌備
  2. 白板畫一個表格，橫軸寫 R／A／C／I 四欄
  3. 把團隊成員名字各寫一張便利貼，貼進對應的欄位同一個人可以同時出現在不同欄
  4. 檢查每一列：A（負責人）那欄是不是都只有一個人兩個人同時「負責」，通常代表沒人真的負責
FRAMEWORK · 要徑法 Critical Path Method

哪一條線卡住，
整個專案就跟著卡住

不是每個任務都一樣重要——有些任務一延遲，全部都會跟著延遲
要徑法（Critical Path Method）
找出專案裡「有相依關係、串起來決定最短完成時間」的那條任務鏈——這條線上的任何延遲，都會直接拖延整個專案；不在這條線上的任務，有一些緩衝空間。
資料來源：PMI《PMBOK Guide》時程管理知識領域
套用在跨單位活動籌備
場地確認 → 邀請函發送 → 名單回覆 → 現場佈置，這條線任何一步delay，活動就延——先看清楚這條線，其他像文宣設計可以晚一點再排。
開會追進度時，先問「要徑上的任務」進度如何，比平均關心每一件事更有效率。
🗒️ 便利貼活動 · 畫出任務相依關係

用便利貼＋箭頭，
找出你的要徑

白板/海報紙＋便利貼＋筆（畫箭頭連線）個人或小組6分鐘
  1. 想一個你正在籌備、有好幾個步驟的專案可以用「跨單位活動籌備」練習，也可以換自己的
  2. 每個步驟寫一張便利貼，先不管順序
  3. 把便利貼依照「誰要等誰完成才能開始」排好，畫箭頭連起來
  4. 找出從頭到尾串起來最長的那一條線，就是要徑沒有連在這條線上的便利貼，代表有緩衝空間
FRAMEWORK · 時程緩衝 Contingency Reserve

行事曆排到100%滿，
就是在等意外發生

今天上午Timeboxing已經提過，這裡是PMI的正式版本
時程緩衝（Contingency Reserve）
在排程裡刻意保留一段沒有排事的時間，用來吸收臨時交辦、突發狀況、估錯的工時——緩衝不是浪費，是讓整個系統不會一有意外就全部延誤。
資料來源：PMI《PMBOK Guide》時程管理知識領域
主管的抓法
要徑上的任務，多抓10–20%緩衝時間；社工/老師的個案工作，緩衝可以抓更高，因為家庭狀況變化本來就難預期。

SYSTEM · 進度追蹤

把成果轉成一份
可以持續追蹤的工作表

從會議紀錄、Email、文件中提取所有工作事項
每件工作至少要有
完成標準、負責人、期限、下一步——缺一項，這件事在追蹤上就會失蹤
狀態欄位
進行中／等待對象／有風險或阻礙——讓你一眼看出卡在哪裡，不用每件事都重新問一次

SYSTEM · 每日工作節奏

建立一套
每天都能執行的節奏

集中處理同類工作
信件、簽核、回覆、資料輸入集中在固定時段，減少任務切換的注意力殘留
保留完整專注區塊
需要思考判斷的工作，安排在精神最好的時段，不要被瑣事切碎
交接筆記
工作結束前，留下「做到哪裡、下一步是什麼」——明天或交接的人不用重新想一次
短暫休息
依疲勞程度安排休息，不用每個人都固定套用25分鐘番茄鐘——效果會隨任務種類和休息長度改變
資料來源：微休息統合分析（短暫休息有助恢復精神、降低疲勞，效果受任務種類與休息長度影響）
每天下班前快速更新進度，每週安排一次完整回顧——系統會失效，通常是因為少了這個回顧動作。
FRAMEWORK · 番茄鐘 Pomodoro

與其說「今天要做完」，
不如說「先做 25 分鐘」

用固定的時間區塊，對抗一直被打斷的一天
番茄鐘技巧（Pomodoro Technique）
設定一段專注時間（原始版本是25分鐘），期間只做一件事，時間到強制休息5分鐘——用倒數的急迫感，對抗拖延與分心。
資料來源：Francesco Cirillo，1980年代末提出
不用照搬25分鐘
回到今天上午學的微休息研究：效果受任務種類影響，需要深度思考的工作可以拉長到45–50分鐘，行政瑣事用短一點的區塊就好。
重點不是計時器，是「先設定一段不被打斷的時間」——這跟前面的Timeboxing是同一件事的兩種做法。
觀念 · 為什麼知道該做，還是沒開始

處理拖延，
從縮小第一步開始

把大任務改寫成小的第一步
不是「規劃下學期課程」，是「打開文件，寫下三個候選主題」——10到20分鐘可以開始的動作
WOOP
願望（Wish）→ 期待成果（Outcome）→ 內在障礙（Obstacle）→ 應對計畫（Plan）
資料來源：WOOP 統合分析（結合心理對比與行動計畫，對目標達成有小到中度效果）
🗒️ 便利貼活動 · 寫出你的WOOP四格

用四張便利貼，
拆解一件你一直拖延的事

四張便利貼＋筆個人4分鐘
  1. 第一張：寫下你的願望（Wish）一件你想推進、卻一直拖延的事
  2. 第二張：寫下期待成果（Outcome）如果做到了，具體會有什麼不一樣
  3. 第三張：寫下內在障礙（Obstacle）誠實面對——是什麼讓你每次都卡住
  4. 第四張：寫下應對計畫（Plan）「如果[障礙出現]，我就[具體行動]」
四張便利貼排成一排，貼在你看得到的地方——跟今天早上那隻「青蛙」便利貼放在一起。
FRAMEWORK · If-Then 行動計畫

「如果……，我就……」

研究上效果最扎實的一個小工具
句型
如果[某個情況出現]，我就[採取某個具體行動]。

例如：「如果上午會議取消，我就先完成活動簡報前三頁。」
在 94 組研究中，If-Then 行動計畫對目標達成呈現中到大的效果——不是心理暗示，是被反覆驗證過的方法。
資料來源：Gollwitzer & Sheeran 統合分析

2026 新知 · 一個容易被忽略的陷阱

AI省下來的時間，
不會自動變成你的時間

傑文斯悖論：資源變便宜，用量反而增加
傑文斯悖論（Jevons Paradox）
AI模型成本持續下降，但不會自動轉化成更高效率——當資源變便宜、變容易取得，整體用量反而會增加。你可能只是做出更多內容、分析更多資料、建立更多工作流，而不是真的少做事。
資料來源：RadarFirst CEO Zach Burnett（Adam Mendler 訪談，2026）
對主管的意義
省下來的時間，如果沒有刻意決定要拿去做什麼，通常會被更多待辦事項填滿——回到今天早上的矩陣：這些省下來的時間，你要主動排進「重要但不緊急」的那一格。
這就是為什麼今天最後要你寫一份計劃書，而不是只教工具——省下的時間需要一個明確的去處。
FRAMEWORK · SMART 原則

寫計劃書前，
先確定目標寫得夠具體

等一下的「成效指標」欄位，就是靠這五個字撐起來的
S 具體
Specific——是哪一件工作、哪一個環節
M 可衡量
Measurable——工時、次數、準時率，有數字才知道有沒有進步
A 做得到
Achievable——這週真的排得出時間去改善它嗎
R 有相關
Relevant——解決之後，對你的工作真的有影響
T 有期限
Time-bound——一週後回頭檢查，而不是「有空再看」
資料來源：George T. Doran, 1981, Management Review
FRAMEWORK · OKR

SMART管好一件事，
OKR管好一整個團隊的方向

個人任務用SMART；帶團隊、對董事會交代方向，用OKR
OKR（Objectives and Key Results）
O目標：一句話說清楚方向，可以稍微有野心；KR關鍵成果：2–3個可衡量的具體指標，證明目標有沒有達成。
資料來源：Andy Grove 提出，John Doerr《OKR：做最重要的事》推廣
套用在拾光教育中心
O：讓每個孩子的課後輔導更有效。KR：家訪完成率100%、課後輔導班表零衝突、董事會報告準時交出——每一項都能對照今天學的方法論去達成。
SMART用在你自己的計劃書；OKR是你以後要帶著整個團隊一起看的方向。
