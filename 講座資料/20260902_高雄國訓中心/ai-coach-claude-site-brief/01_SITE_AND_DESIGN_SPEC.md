# 網站、互動與視覺規格

## 1. 使用者與使用場景

### 講師 Simon

- 使用筆電接投影機，可能同時開啟投影片、講師控制台與三個 AI 工具。
- 現場操作必須少點擊，不應在資料夾與分頁之間來回找提示詞。
- 需要看到現在時間、整場剩餘時間、目前段落、下一頁與當頁講稿。
- Live Demo 期間要能快速複製提示詞與案例資料。
- 網路或 AI 回覆異常時，要能在 5 秒內切換備援成果。

### 現場學員

- 約 50 位運動教練，多數第一次接觸 Claude。
- 主要看投影幕，不要求同步登入與操作。
- 課後會用手機掃描 QR Code，取得提示詞和練習資料。
- 來源包含國小至大學、學校與協會，運動專項不一。

### 主辦單位

- 需要一個看起來完整、清楚、可掌握課程內容的入口。
- 不需要後台登入或蒐集個資。

## 2. 資訊架構

### `/` 學員入口

頁面順序：

1. Hero：課程名稱、日期、時間、地點、講師。
2. 一句說明：看講師把教練工作放進 AI 跑一次，回去照著流程練習。
3. 今日流程：第一堂、休息、第二堂、問答。
4. 三個工具定位卡：ChatGPT、Gemini、Claude。
5. 今天的案例：林教練與 8 週訓練任務。
6. 提示詞工具箱：依步驟展開、複製。
7. 案例資料下載。
8. 課後 30 分鐘練習。
9. 資料安全提醒。
10. 官方網站與參考資料。
11. 講師資訊。

課程進行中可將「提示詞工具箱」收合，避免學員提前滑到答案；此功能用簡單設定值控制，不需後台。

### `/slides`

- 16:9 投影片。
- 全螢幕顯示。
- 鍵盤：左右方向鍵、Page Up/Down、空白鍵下一頁、Home/End、`O` 縮圖總覽、`F` 全螢幕、`B` 黑幕、`N` 顯示/隱藏頁碼。
- 觸控：左右滑動。
- URL 支援 `?slide=23` 或 hash，重新整理後回到同頁。
- 顯示目前頁碼與段落色標，但保持低干擾。
- Demo 頁要明確顯示「現場操作」與「備援畫面」狀態。

### `/presenter`

桌面版採三欄：

- 左欄：段落與投影片清單。
- 中欄：目前投影片預覽、上一頁、下一頁。
- 右欄：當頁講稿、時間提醒、Demo 操作與備援成果。

控制台固定區：

- 現在時間。
- 整場計時：10:45 開始、12:45 結束。
- 段落倒數，可選第一堂 45 分、休息 15 分、第二堂 45 分、問答 15 分。
- `開始／暫停／重設／跳到下一段`。
- 進度若超前顯示綠色，落後 3 分鐘黃色，落後 7 分鐘紅色。
- 快速按鈕：Claude、ChatGPT、Gemini、學員入口、新視窗投影片、黑幕。

講稿卡內容：

- 本頁要講的重點。
- 建議口語講法。
- 可向學員提的問題。
- 本頁預計時間。
- 若時間不足可刪掉哪一句或哪個互動。
- 下一頁轉場句。

Demo 卡內容：

- 情境說明。
- 要貼入的資料。
- 完整提示詞。
- 複製提示詞按鈕。
- `已完成` 勾選。
- 預期畫面重點。
- 可能發生的問題。
- `顯示備援輸出` 按鈕。

### `/resources`

課後資源獨立頁，也可以由首頁錨點進入。內容必須能在手機閱讀。

### `/print`

- 白底列印版。
- 一頁一張投影片。
- 可選「只印投影片」或「投影片＋講師備註」。
- 不印控制按鈕。

## 3. 投影片設計系統

### 視覺感受

要有訓練場、戰術板與資料工作台的感覺。畫面乾淨、偏深色、資訊有層級。避免科技藍漸層、發光機器人、大腦電路圖、AI 人形與制式商務簡報圖庫。

### 色彩

- 主背景：`#0D1110`
- 卡片背景：`#171D1B`
- 次層背景：`#222A27`
- 主文字：`#F3F2EC`
- 次文字：`#B9C0BC`
- 強調綠：`#A8E05F`
- Claude 標籤：`#D97757`，只作小面積識別
- Gemini 標籤：`#7C9CFF`
- ChatGPT 標籤：`#45B69C`
- 警示：`#FFB84D`
- 風險：`#FF6B6B`

所有顏色需通過基本對比度檢查。工具色只作區分，不模仿官方 Logo。

### 字體

- 中文：Noto Sans TC 或可離線使用的台灣繁中字體。
- 英數：Inter。
- 投影片標題：最小 48px。
- 主要內文：最小 30px。
- 表格：最小 24px。
- 註記：最小 18px，不能承擔核心訊息。

### 版型

請建立可重用的 slide type：

- `title`：封面或段落頁。
- `statement`：一句關鍵觀念。
- `comparison`：二至三欄比較。
- `workflow`：步驟流程。
- `case`：人物與任務情境。
- `prompt`：提示詞，含逐段高亮。
- `demo`：Live Demo 操作頁。
- `output`：AI 結果重點或備援輸出。
- `table`：資料與課表。
- `warning`：資料安全、檢查點。
- `question`：現場提問。
- `ending`：結尾與 QR Code。

每頁最多一個主要概念。投影片若出現長提示詞，投影畫面只顯示結構與關鍵句，完整版本放講師控制台與學員資源頁。

## 4. 互動與現場節奏

本課程沒有學員完整跟做，但需要保留參與感：

- 舉手：目前最花時間的工作是哪一種？
- 快問快答：這份課表還缺什麼資訊？
- 選項卡：該用 ChatGPT、Gemini 或 Claude？
- 找錯：AI 產出的訓練安排哪一點不能直接採用？
- 現場加條件：請一位教練提供運動項目、對象與限制，講師當場改寫成提示詞。

網站不需即時投票系統。投影片顯示問題，講師以舉手或口頭回覆帶過。

## 5. Live Demo 快速列

講師控制台最上方固定一列：

1. `比較任務`：開啟簡短提示詞。
2. `Claude 專案`：開啟 Claude。
3. `整理資料`。
4. `找缺口`。
5. `8 週架構`。
6. `展開一週`。
7. `臨時改場地`。
8. `行政文件`。
9. `選手通知`。
10. `成果紀錄`。

每個項目要顯示未開始、進行中、已完成。狀態只存在本機。

## 6. 內容資料模型

投影片建議資料結構：

```ts
type Slide = {
  id: string
  section: 'opening' | 'ai-basics' | 'tool-choice' | 'prompting' | 'break' | 'claude-demo' | 'safety' | 'practice' | 'ending'
  type: 'title' | 'statement' | 'comparison' | 'workflow' | 'case' | 'prompt' | 'demo' | 'output' | 'table' | 'warning' | 'question' | 'ending'
  title?: string
  eyebrow?: string
  content: unknown
  durationSeconds: number
  speakerNotes: string[]
  audienceQuestion?: string
  trimIfLate?: string
  transition?: string
  demoStepId?: string
}
```

Demo 建議資料結構：

```ts
type DemoStep = {
  id: string
  title: string
  goal: string
  tool: 'ChatGPT' | 'Gemini' | 'Claude'
  requiredFiles?: string[]
  prompt: string
  expectedSignals: string[]
  failureModes: string[]
  backupOutput: string
}
```

## 7. 離線與故障備援

現場可靠性優先。至少做到：

- 核心網站資源本機可用。
- 所有圖片、字體與案例資料不依賴即時外站 CDN。
- 每段 Demo 的預期輸出存在本地 Markdown/JSON。
- `備援模式` 打開後，在投影片中顯示預先輸出內容，右上角標示「預先準備之示範結果」。
- 保留 PDF 版投影片。
- README 提供「網路全斷」操作清單。

常見狀況與網站處理：

| 狀況 | 處理 |
|---|---|
| AI 回覆太久 | 顯示備援輸出，說明現場先看已準備結果 |
| 帳號被登出 | 開啟備援，不在台上重設密碼 |
| 免費額度用完 | 使用講師已確認可用的帳號；備援輸出持續可用 |
| 投影畫面卡住 | 控制台提供重新開啟投影片視窗按鈕 |
| 同步失效 | 投影片與控制台可各自切頁，頁碼仍可從 URL 指定 |
| 網路全斷 | 投影片、案例、講稿和備援輸出照常使用 |

## 8. 文案與介面語氣

- 使用台灣日常用語。
- 按鈕寫「複製提示詞」「開啟 Claude」「顯示備援結果」，不要寫抽象名詞。
- 提醒寫清楚行為，例如「請先把姓名換成代碼再上傳」。
- 不宣稱任何單一工具一定比較準、比較聰明。
- 工具功能與方案可能變動處標記「介面與方案依當日官方版本為準」。

### 開場說明

今天不要求大家跟著完成一整套操作。講師會把教練常見的工作資料放進 AI，從第一次不夠完整的回答開始，示範怎麼補資料、修改、檢查，再整理成能交給學校、協會或選手的內容。課後可以下載同一套虛構資料，照著提示詞自己練習。

### 今日流程

**第一堂｜認識生成式 AI 與工具選擇**  
認識 ChatGPT、Gemini、Claude 的使用差異，觀察同一項教練工作交給三個工具後，結果和操作流程會怎麼變。

**第二堂｜Claude 教練工作實戰**  
從選手資料整理開始，完成 8 週訓練架構、單週課表、臨時調整、校方計畫與選手通知。

### 三個工具

**ChatGPT**  
適合用對話反覆拆解工作、整理多種內容、分析資料與製作不同形式的成果。若平常的工作類型很多，可把它當成通用工作台。

**Gemini**  
適合已大量使用 Gmail、Google 文件、雲端硬碟與其他 Google 服務的人。可從原本的 Google 工作環境接續處理資料；實際整合能力依帳號與管理員設定而異。

**Claude**  
適合閱讀較長資料、整理脈絡、依照條件撰寫完整計畫，並可使用 Projects 保存背景資料、利用 Artifacts 或檔案功能整理可重複修改的成果。本課程以 Claude 做主要示範。

### 今天的案例

林教練負責高中田徑短跑組，8 週後有重要比賽。手上有 12 位選手的基本狀況、出席與測驗資料，學校希望看到訓練目標、安全說明與成果紀錄。訓練進行到一半，操場臨時停用。今天會看林教練如何把同一批資料一路整理成可用成果。

### 課後練習

找一件下週真的要完成的工作，先移除姓名、聯絡方式、學籍、傷病細節等可識別資料，再依序做：

1. 用兩三句話交代任務。
2. 請 AI 先問你缺少的資訊。
3. 補上對象、時間、資源、限制與要交出的格式。
4. 先做架構，再展開細節。
5. 挑出三個需要教練自己確認的地方。

### 資料安全提醒

練習時使用本網站提供的虛構資料。實際工作資料請先匿名化，不要上傳姓名、身分證字號、電話、地址、完整生日、學號、可辨識的傷病或醫療紀錄。學校或協會若已有 AI 使用規範，以單位規範為準。

## 10. 無障礙與響應式

- 所有按鈕可用鍵盤操作。
- 有清楚 focus 樣式。
- 色彩不是唯一狀態提示。
- 投影片可在 1366×768 及 1920×1080 完整顯示。
- 學員入口支援 360px 寬度。
- Prompt code block 可水平捲動，不能撐破版面。
- 動畫遵守 `prefers-reduced-motion`。

## 11. 不要實作的功能

- 不做帳號登入。
- 不做即時聊天室。
- 不做學員 AI 代理或內嵌模型。
- 不做即時多人同步投票。
- 不蒐集選手資料。
- 不自動把任何資料送往第三方。
- 不用 Canvas 或 WebGL 做花俏動畫。
