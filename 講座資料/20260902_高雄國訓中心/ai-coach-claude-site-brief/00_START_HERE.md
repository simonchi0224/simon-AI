# Codex 建置任務總說明

## 專案名稱

AI 教練工作術：運用 Claude 協助訓練規劃與行政工作

## 請先讀完

你正在協助講師 Simon 季祥，建置一個可在實體講座現場使用的「講師入口網站＋網頁投影片系統＋學員課後資源頁」。請先完整閱讀本資料夾所有檔案，再開始實作。不要先產生一套空泛的簡報模板，也不要自行縮減逐頁內容。

本案的核心是講師現場操作。學員約 50 人，對 Claude 陌生，主辦單位希望以講師講解為主。講師會依照預先準備的劇本，把資料與提示詞放入 ChatGPT、Gemini、Claude，讓學員直接看到從原始任務到可交付成果的完整流程。

## 課程定位

這堂課不做工具功能導覽大集合。課程要讓教練看懂：

1. 同一件工作放進不同 AI，操作方式與整合情境會有差異。
2. AI 第一次生成的內容通常只能當草稿，教練要補背景、限制與判斷標準。
3. 同一批資料可以延伸成訓練架構、單週課表、行政計畫、臨時變更通知與成果報告。
4. 教練必須保留專項判斷，尤其是傷病、負荷、恢復與選手個別狀況。
5. 選手姓名、傷病、聯絡方式、學籍與可識別紀錄不能直接貼進個人版 AI 工具。

## 課程故事線

主要案例採虛構情境：

> 林教練派駐高中的田徑短跑組，負責 12 位高一至高三選手。8 週後有一場重要賽事，學校要求提出訓練計畫、安全說明與成果紀錄。林教練手上有選手概況、近期出席與測驗資料，但資料散落在表格與訊息中。訓練進行到一半，操場又因工程臨時停用一週。

講師會依序示範：

- 先用模糊的一句話請 AI 排課表，讓大家找出問題。
- 補上對象、目標、器材、時間與不可碰觸的限制。
- 請 Claude 先整理資料並列出缺口，不急著直接產出課表。
- 建立 8 週訓練架構，再展開其中一週與一堂課。
- 遇到操場停用，請 Claude 保留訓練目的並修改安排。
- 把同一批資料轉成校方計畫摘要、選手通知與成果紀錄表。
- 最後回頭檢查 AI 哪些判斷沒有依據，哪些內容必須由教練決定。

田徑只是示範載體。投影片與講稿須提醒學員，工作方法可以換到游泳、羽球、舉重、球類及其他運動；實際訓練內容仍由專項教練負責。

## 網站必須包含的三種入口

### 1. 講師控制台 `/presenter`

講師自己使用。要能快速進入每一段投影片、查看當頁講稿、倒數計時、複製提示詞、開啟三個 AI 工具，以及切換備援成果。

### 2. 全螢幕投影片 `/slides`

投影幕使用。16:9、字大、畫面乾淨，可由鍵盤或控制台切換。不要把講稿塞在投影畫面。

### 3. 學員入口 `/`

學員掃 QR Code 開啟。課程前可看到講座資訊；課後可以取得提示詞、虛構案例資料、練習步驟、官方工具連結與資料安全提醒。

## 實作原則

- 優先做成無需後端即可運作的網站。課程內容以本地資料檔管理，不把提示詞寫死在 UI 元件裡。
- 網路不穩時，投影片、講稿、案例資料與備援成果仍須正常顯示。
- 外部 AI 網站無法離線；現場失敗時，講師要能一鍵切換到預先準備的備援輸出。
- 不串接 OpenAI、Google、Anthropic API，不在網站中存放任何 API Key。
- 網站不能真的蒐集學員資料。回饋表與下載連結先做成可設定欄位。
- 所有內容使用繁體中文，台灣用語。
- 不使用未經授權的國訓中心、Anthropic、OpenAI、Google 商標圖檔。工具名稱可用文字與簡單幾何標籤呈現。
- 介面要像講師現場會真的使用的工作台，不要做成企業官網或行銷 landing page。

## 技術選擇

若目前資料夾已有專案，先檢查既有技術與 `AGENTS.md`，盡量沿用。若是空資料夾，建議：

- Next.js App Router＋TypeScript
- Tailwind CSS 或簡單 CSS Modules
- 內容使用 TypeScript/JSON/Markdown 資料檔
- `localStorage` 儲存講師偏好、計時與目前頁碼
- `BroadcastChannel` 同步講師控制台與投影片視窗
- 可安裝 PWA 或至少在完成一次載入後快取核心靜態資源
- 不導入資料庫、登入系統與付費服務

技術選擇可以因現有專案調整，但功能與現場可靠性不能縮水。
