別人整理好的 83 個 AI skill，
可以直接裝嗎？

Simon Chi 季祥 2026年11月18日 5 分鐘閱讀

最近看到一張圖，標題是「AI 短劇 skill 83 個整理好了」，Claude Code 和 Codex 都能裝。連盲測結果和推薦組合都排好了，看完很想直接一鍵裝起來。但整張圖我覺得最值錢的一句話，被放在最底下的小字：「有的會引導你下載 exe 安裝檔」。

skill 只是一個資料夾，但它拿到的權限跟你的 AI 一樣大

先講清楚 skill 是什麼。它就是一個資料夾，裡面一份 SKILL.md 寫著「遇到這類任務，照這個步驟做」，有些會附幾支腳本。Claude Code 或 Codex 讀到之後，就會照著執行。

問題就在「照著執行」。你的 AI 代理人能讀你電腦裡的檔案、能跑指令、能連網路，skill 裡寫什麼，它就用這些權限去做什麼。一份寫得好的 skill 讓 AI 變成專業編劇；一份動過手腳的 skill，可以叫它去下載一個安裝檔回來跑。從外表看，兩者都只是幾份文字檔。

這份清單做對了一件很少人做的事

原始資料來自 GitHub 上的 awesome-short-drama-skills。我去翻了它的說明，整理的人總共看過 203 個 repo，收了 83 個，剩下 104 個沒收，而且每一個排除的理由都逐條記錄在檔案裡，其中就有「照搬熱門 skill、再誘導下載安裝包」的仿冒品。

大多數懶人包只告訴你「推薦什麼」，很少告訴你「刷掉了什麼、為什麼」。後者才是判斷一份清單可不可信的地方。它還做了盲測：拿 10 個編劇 skill 跟不裝 skill 的結果比，請不同家的模型當評審，只有 4 個三場都贏。光這兩點，就比一般轉貼的清單可靠很多。

就算清單可信，我還是自己看了一遍

可信的清單幫你縮小範圍，但它審的是當時的版本，repo 隨時會更新。所以我挑了盲測全勝的那 4 套，請 Claude Code 先把原始碼下載到隔離的暫存區，逐一檢查裡面的腳本會連到哪裡、會不會去抓執行檔回來跑。

結果是 4 套加起來 61 個 skill，其中三套完全是文字檔。唯一附程式的那套，腳本只會連 OpenAI、火山引擎 Seedance、MiniMax 這幾家的官方 API，而且要你自己填 API key 才會動；其他就是在本機開一個預覽頁面，跟呼叫 ffmpeg 剪片。另外有一套是用壓縮檔發佈的，解開來裡面就是 6 份說明文件。整個過程大概十分鐘。

實際怎麼做

裝任何第三方 skill 之前，可以直接把這段丟給你的 AI 代理人：「先不要安裝。把這個 repo 下載到暫存資料夾，列出所有腳本檔，檢查有沒有下載執行檔、連到哪些網址、有沒有 hook 或會自動執行的設定，用表格回報給我，等我確認再裝。」

裝的時候，再多做兩個小動作

第一，裝你審過的那一份。很多安裝指令會重新從網路抓最新版，那一份不一定是你剛剛看過的。我的做法是直接把審過的檔案複製過去，順手記下版本號，之後要更新就重新審一次。

第二，裝在專案裡，不要裝成全域。61 個短劇 skill 如果裝在全域，之後不管拿 AI 處理什麼工作，它都會先讀過一輪這些編劇說明，既浪費也容易誤觸發。把它們放在一個專門做短劇的資料夾裡，只有在那裡工作時才會載入。用不到的能力，就不要讓它隨時待命。

對公司來說，這是下一個要管的地方

我在〈你的同事已經會自己做 AI 工具了〉那篇講過，員工自己動手是好事，但公司要知道他們在做什麼。skill 是同一件事的下一步：同事從社群上看到一張懶人包，五秒鐘就能把一整包別人寫的指令，裝進一個能碰公司檔案的 AI 裡。

這不需要禁止，只需要一條很簡單的規則：第三方 skill 先審再裝，裝在專案裡，記下來源和版本。這跟〈Codex 不是工程師的專利〉裡講的「先隔離、再核准」是同一套邏輯，只是這次要隔離的，是別人寫給你 AI 的那一份說明書。
